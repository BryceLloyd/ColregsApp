# CLAUDE.md: COLREGs Trainer

Guidance for Claude Code when working in this repo.

## How to work here
Give concise, opinionated answers and keep the architecture simple. Build iteratively: propose a scoped step, get approval, then build it. The app is tested on an iPhone, so the layout must work on a phone first.

## What this is
A static, mobile-first PWA for learning the COLREGs. There is no framework and no build step. It was originally a single HTML file and has been split into plain files.

## Architecture (read before editing)
- **Classic scripts sharing one global scope.** `index.html` loads `js/config.js`, then `js/00-core.js` … `js/99-boot.js` in numeric order as ordinary `<script>` tags, not modules. Top-level `const`/`let`/`function` in one file are visible to the files after it.
  - Keep top-level code that runs at load time in the right order. Add new files with a number that places them correctly.
  - Function bodies can reference anything, because they run later.
  - When you add a file, also add it to `index.html` and to `FILES` in `sw.js`.
- **Views:** `#home` (Watchkeeper-first: best endless watch, big Play, practice missions, then Challenge and the learning sections), `#sec` (learning sections), `#app` (scenario simulator), `#play` (Watchkeeper). Switch between them with `show(name)`. Overlays (`.ov`) open with `openOv(id)` and close with `closeOv(id)`.
- **Older iPhones:** `00-core.js` adds a `findLast` fallback and `rrect()` (use it instead of `ctx.roundRect`); the target is iOS 15+. `loop()` schedules the next frame first and wraps the work in try/catch, so one error can't freeze the app. Audio unlocks on the first touch and resumes after a lock (05-audio). Watchkeeper pauses when the page is hidden, and a ResizeObserver keeps the chart canvas matched to `#pStage`.
- **Phone layout:** buttons are at least 40–44 px. Watchkeeper has one horn row; the fog toggle (`#pFogBtn`) joins it in fog missions, and the Pass row (`#pHornChan`) shows only while you're overtaking in a channel. Helm and engine stay side by side (engine wider; "Astn" on narrow phones). Ships in an encounter that are still off the chart get an edge arrow with their range. Encounter alerts show in the hint bar only (no toast). In endless, 🏠 twice ends the watch and keeps the score. The debrief offers the next practice mission. Landscape on a phone shows a "turn your phone upright" screen (`#rotate`). The smoke tests include a 320 × 568 layout check.
- **One animation loop:** `loop()` in `13-sim-flow.js`. It drives the simulator when `view==='app'` and calls `wkFrame()` when `view==='play'`. It also ticks buoy-light animation.

## Key data (append, don't reorder)
- `SCEN` (`01-scenarios.js`): animated scenarios. **The array index is the scenario's ID**, and these maps refer to scenarios by index: `LEVELS[].pool`, `PRACTICE`, `NIGHT_OK`, `TYPE_SWAP`, `ANGLE_OK`, and the overrides in `dangerWhy()`. Add new scenarios at the end.
  - Fields: `cat, title, prompt, other{type,h,v,T|x,y,dx}, own{type,v}, correct[], best, rule, ok, bad, tip`.
  - Optional fields: `night, fog, radar, channel, lane, laneDeg, laneT, turnDeg, hazards[[x,y,r]], tss{cx,cy,dir}, wind, region, otherReacts, freezeAt`.
  - Units are arbitrary. Your vessel starts at the origin heading 0°. With `other.T`, the other vessel is placed so that both reach the collision point at time `T`.
- `LEVELS` (`02-…`): Challenge levels. `sims` scenarios are drawn from `pool`, plus multiple-choice questions from `mcq: [[kind, n, topic]]`.
- `RULEQ`, `LIGHTQ`, `SPOT`, `ORDERQ`: question banks. `makeQs(kind, n, topic)` mixes formats.
- `BUOYS` (`06-buoyage.js`): IALA marks. **`REGION = 'A'` is the standard** (South Africa). Region B appears only as a Learn toggle and in one labelled scenario.
- Watchkeeper (`15-…`): `MISSIONS`. `m1`–`m6` are the practice missions; `m7` is endless.
  - `classify(me, target)` decides head-on, crossing, or overtaking, and from that give-way or stand-on.
  - `encTick` and `wkGrade` are the referee. An encounter is created when a ship spawns, and its baseline is your ordered course and speed at that moment.
  - Only actions taken before CPA count. Actions count from the moment they're ordered, but only if the order is held for 1.5 real s (`e.actP` → `e.act`), so a flick of the helm isn't "substantial action". Substantial = 30°+ from the course at spawn or speed halved. A smaller alteration held 1.5 s (`e.partD`, `e.partCut`) is named on the card: 15–29° or a 25–49% speed cut −40 (Rules 8(b) & 16), less than that −100. While an encounter is on, the hint bar shows "You: +20°, 6 kn" (your own alteration since she appeared: a fact, not advice), the 💡 −20 hint is a small outline chip, and the target card is compact.
  - An encounter that never raised an alert (never a risk of collision) and that you took no action for closes quietly (`e.silent`): not scored, not in the debrief, not counted for endless levels.
  - No toasts during an encounter that reveal your role or the answer; verdicts come only after it (content rule).
  - Overtaking: slowing to her speed or less and not closing for 3 s closes the encounter as kept clear (`droppedBack`). If you later close in on her again, one new encounter opens for that ship.
  - Rule 18: `WK_TYPES` gives each vessel type a `rank` (who keeps out of whose way), speed, rule and day-shape description. `classify` applies Rule 13 first, then Rule 18 between different ranks (`cl.r18`), then Rules 14/15/17 between power-driven vessels. Mission encounters can carry a type: `'xport:fishing'`, or `'xport:r18'` for a random one from `R18_POOL`. The type is shown only by day shapes (chart and target card) and named after the encounter.
  - Horn (Rule 34(a)), in `hornGrade`: the avoiding turn needs • (starboard) or • • (port) within `HORN_WIN` (8 real s): +15 / missing −10 / opposite −20. Going astern needs • • •: +10 / −10. Any •, • • or • • • in the encounter that matches no turn (`P.turns`, logged per 10° of ordered course) or astern order costs −15. Judged only in the result card.
  - Ships spawn beyond the edge of the chart (`wkView`/`inView`, at most the 3 nm view): crossing and head-on ships keep the same meeting point but with more lead time; overtaking/overtaken ships start just off the top/bottom. Collisions happen at `COLLIDE` (0.1 nm, the icons overlapping) with any ship, including one whose encounter is over (−1 heart, −100, listed in the debrief as `P.lateHits`); one per contact (`a.inContact`, cleared once you're 2×`COLLIDE` apart); she stays on the chart and a 💥 marks the spot. Ships only spawn at a steady speed; an overtaking target is slower than you (or becomes head-on traffic if you're stopped). Closing on a ship you've already dealt with gives a "⚠ Watch …" warning and a red ring, not a new encounter (only `droppedBack` reopens one). Giving-way ships resume their course only once that won't cut back across you, and a ship whose encounter is over that is give-way to you and closing again (CPA < 0.25 nm) takes the smallest turn that clears you. An encounter also ends when she'll pass 0.5 nm+ clear and the range has hardly changed for 6 s (running alongside). The helm can't order more than 170° ahead of the heading, so holding it keeps turning one way. A stopped ship barely turns. Waypoints count within 0.2 nm or once passed abeam within 1 nm (`wpPassed`).
  - Spawning waits until no ship is near. A ship whose encounter is done and that is past CPA or passing 0.5 nm+ clear (and 0.5 nm+ away) doesn't count as near.
  - An `enc` entry can be an array to spawn ships together (`['xstbd','xport']`); they reach your track at the times in `GROUP_T`.
  - Other ships keep clear of each other: `aiAvoidAis` (the give-way ship turns by the rules; a stand-on ship acts if the other can't, a rogue or NUC/RAM never does) and `aiLastResort` (any ship about to pass within 0.18 nm of another takes the smallest turn, starboard first, that clears, or stops; slow ships are the obstacle). A new ship waits if it would start on top of or soon run into one already out there (`aiClash`).
  - Two at once: if you're stand-on to one ship but alter for an overlapping give-way encounter, that's allowed (Rule 2(b)): `e.excused`, +40 instead of the Rule 17 penalty.
  - Rogue ships (`m6`): an `enc` entry ending `!` is a rogue give-way ship that holds course and speed; `?` makes it rogue half the time. For your stand-on encounter, `dueT` is when a compliant ship would act; from `ROGUE_AFTER` (3 real s) later it's "apparent" and you may act (Rule 17(a)(ii)) without the Rule 17(a) penalty. `rogueGrade`: five short +20 / −15 (Rule 34(d)), acting at 0.5 nm+ +60, later +30 (17(b)), never −60, port turn for a ship on your port side −40 (17(c)). Against a rogue crossing from port, stopping or a bold 90° starboard turn at full speed works; slowing while turning to starboard lets her catch you.
  - Channel missions (`18-watchkeeper-channel.js`, `m3`): a mission with `chan:{pts,hw,bank}` draws land, shallows, the dredged channel and Region A lateral marks (red to port, green to starboard going in). `chanPos` gives the signed offset (+ = starboard side going in) and distance along. Leaving the channel (|off| > `hw`) runs you aground: −1 heart, −100, reset inside, stopped. Waypoints count when you're abeam of them. `chanTick` scores Rule 9(a) time on the starboard side (debrief: 90%+ +100, 70%+ +40, else −50) and one prolonged blast (▬) within 1 nm before each 25°+ bend (Rules 9(f) & 34(e), +15 / −10). `'chan:out'` spawns an outbound ship that follows her own starboard side; that encounter (`cl.type 'chan'`) is graded by `chanEncGrade`: your side at CPA (+60 / −60) and passing distance, not by a 30° turn, and channel bends don't need Rule 34(a) signals.
  - Channel traffic (`chanSpawn`): `'chan:cross!'` is a yacht or fishing boat waiting at the channel edge that sets off to cross your bow just as you arrive (Rule 9(b)–(d)); `'chan:cross?'` does so half the time, otherwise she waits until you're past. Graded by `chanCrossGrade`: five short +20 / −15, slowing down +40, keeping going −40; a craft that waits: holding course +40. `'chan:over'` is a slow ship ahead on her starboard side: signal ▬ ▬ • • (pass on her port side, the second horn row "Pass", shown only in channel missions), she replies ▬ • ▬ • and moves over (`e.agreedT`); ▬ ▬ • gets five short (no room). `chanOverGrade`: signal and agreement before passing +20, none −30, wrong side −20; staying astern +30. That encounter only ends once you're 0.3 nm past her, and Rule 9(a) time doesn't count while you overtake with her agreement.
  - Night missions (`19-watchkeeper-night.js`, `m4`): `night:true` turns the chart into radar (other ships are anonymous echoes: no hull, heading line, trail or day shapes) and shows the `#pBridge` strip above it: each ship within 5 nm and 90° of your bow drawn with `lightsSeen()` at her relative bearing. At the alert, `lightsWords()` records what lights she showed and what they mean; the result card shows it. Don't put "being overtaken" in a night mission: she'd be behind you, out of the bridge view.
  - Fog missions (`20-watchkeeper-fog.js`, `m5`): `fog:true` = radar echoes only (no bridge view), start at half speed. Every encounter becomes `cl.type 'fog'` (geometry kept in `e.geo`): no stand-on or give-way, and no Rule 34(a) signals or Rule 18. `fogGrade`: safe speed at detection ≤ `FOG_SAFE` +20 / −30; avoiding action in ample time +60 (later +30, none −80; staying at steerage way and passing 0.4 nm+ clear +30); a port turn for a ship forward of the beam (unless overtaking her) or a turn towards one abeam/abaft (not dead astern) −50 (Rule 19(d)); after hearing her fog signal forward of the beam while she's closing (`heardT`), ordered speed ≤ `FOG_STEER` +30 / −30 (19(e)); any •, • • or • • • −10. No action and she passed 0.5 nm+ clear: +20 (nothing needed). No time bonus in fog. Your fog signal is an automatic controller toggled by `#pFogBtn` (▬ every 2 min making way, ▬ ▬ stopped; Rule 35); the debrief scores time on (90%+ +100, 50%+ 0, else −100). Other ships sound ▬ (power) or ▬ • • (special types) every 2 min, heard within 2 nm and shown on the chart at a fuzzy bearing; in fog they act too (starboard for a ship forward of their beam).
  - In-play feedback (`21-watchkeeper-feedback.js`): the result card no longer pops up by itself. When an encounter is graded, `showResult` floats each scoring note up from your ship (`popText`, e.g. "+25 Rule 13", label from the note's last "(Rule …)" via `popLabel`; horn notes, Rules 34 & 35, pop as "✓ Horn +15" / "✗ Horn −10") and puts a one-line verdict in the hint bar for 8 s (worst mistake or "well handled"); tapping it opens the full card (`openResult`, pauses while open). With "Pause to explain mistakes" on (default, `localStorage wkPauseErr`) a mistake pauses the game without covering the chart; ▶ in the hint bar resumes. Never pauses when `P.m.endless`. `muted` (05-audio, `#pMute`, `localStorage colregsMute`) silences all sounds. Waypoints, bend signals, hints, groundings and collisions also pop.
  - Home & endless (`22-watchkeeper-home.js`): `renderHome()` runs on every `show('home')`: best endless score and level, and a practice tile per mission from `MISSION_META` (icon, what it trains, rules, `ref` score). Stars from the saved best: 1 for finishing, 2 at 60% of `ref`, 3 at 85%. Endless (`m7`, `endless:true`) copies the mission in `endlessSetup`, extends the route as you go (`endlessExtend`), and `endlessFeed` queues one ship at a time from every `ENDLESS_LEVELS` entry unlocked so far (a level per 5 finished encounters; later levels shorten the spawn gap `m.gap`). Levels 6–8 bring night, fog and busier daylight (`phase`); after that `PHASE_CYCLE` keeps night, fog and day coming round with a shrinking gap (`endlessGap`, not below 0.8; 2 in fog). `endlessSetPhase` switches `P.m.night`/`P.m.fog`, the bridge view and the fog button, only between encounters; no "being overtaken" ships at night. Fog signal time is scored against time spent in fog (`F.inT`). The header reads "⚓ Level 6 🌙". Traffic spawns wherever you're heading. Hearts (every mission): only a collision, a grounding or a close call (the grader's "Close quarters" note, in `showResult`) costs one; other mistakes cost points only. In endless, 5 clean encounters in a row win one back (max 3). Never pauses. Best score and level saved as `wkBest_m7` and `wkBestLevel`.
  - Time scale: `WK_TS = 20` (×20 real time).
- Study record (`23-study.js`): every answer is logged by rule in `localStorage colregsStudy` (`study.r[rule] = {n, ok, h: last 10 as '1'/'0'}`). Quiz and Challenge questions log through `mountQ` (`qKeys`: rules cited in the explanation, else worked out from the topic; buoyage → `IALA`, flags → `Flags`), scenarios in `decide()` (`sc.rule`), Watchkeeper notes in `showResult` (`studyEnc`, the rules each note cites; collisions and close calls count against Rule 8). Cite rule numbers in new notes and explanations so they're logged.
  - The home page rule map (`renderRuleMap`, `RULE_INFO` short paraphrased summaries, `RULE_GROUPS`, `RULE_MISSION`) colours each rule by its last 10 results and lists up to 3 weak rules; tapping one opens `#ovRule` with the summary, your record, and where to practise.
  - Mistakes deck and mock exam (`24-review.js`): any rule you get wrong goes into `study.d[rule] = {b: box, due}` (due now). `startReview` asks one question per due rule (up to 10) from `reviewPool()` (every quiz-format question, tagged with `qKeys`); right moves it up a box (1, 3, 7, 21 days, then out), wrong brings it back in 10 min. `startMock`: 30 questions (`MOCK_MIX`), no feedback until the end (`mountQ` `silent`), pass mark 80%, breakdown by part, what you missed; best in `colregsMockBest`. Both run in the `#sec` view through `qRun`. Every rule on the map must have at least one quiz question (a smoke test checks).
  - Records (`25-records.js`, `#ovRecords`, 🏆 in the home header or tap the best-watch line): three tabs. **Watchkeeper is the main board**: your top endless watches with your name (`wkBestRuns`, top 50, `recordWatch` from `endlessEnd`, which also shows "#2 of your watches" in the debrief) and each practice mission's stars and best. **Challenge** (`14-leaderboard.js`, `colregsLocalBoard`) and **Mock exam** (`colregsMockRuns`, last 20) are personal. One name for everything (`colregsNick`). The future shared leaderboard (5c) is for endless Watchkeeper only.
  - First launch shows `#ovWelcome` (skipped if there's already progress; `colregsSeen`). On iPhone in Safari, home shows an install hint (`colregsInstallOff` hides it). `navigator.storage.persist()` is requested at load. ⚙️ How to play has a backup code (`CT1.` + base64 JSON of every `wkBest*`/`colregs*` key) to move progress between browsers or into the installed app, which has its own storage.

## Content rules
- Paraphrase the rules. Never paste long verbatim passages of official text. Always cite the rule number.
- During Watchkeeper encounters, **never reveal the player's role or the answer**. The only exception is the paid 💡 hint, which costs −20. Explain the role and answer after each encounter, in the result card and the debrief.
- A wrong answer that still passes clear must say why it was dangerous (`dangerWhy`).
- Buoyage scenarios must not show the hazards until the player has answered.
- Use sentence case. Use plain South African/UK English. Keep the tone concise.

## Commands
- `npm run dev`: local server on port 5173.
- `npm run check`: syntax-checks every JS file.
- `npm test`: Playwright smoke tests (`CHROMIUM_PATH=…` to use an existing Chrome).

The smoke tests seed `Math.random`, so every run plays the same traffic and results repeat exactly; stress-test missions separately with random traffic over many runs.

Run `npm run check && npm test` before committing, and check its exit status (don't pipe it through grep). If you change scenario geometry, the test "correct answers pass clear" must still pass.

## Deploy
GitHub Pages from the `Website-Dev` branch (root): https://brycelloyd.github.io/ColregsApp/. Storage is browser-only for now (`localStorage`); leave `js/config.js` blank. **Bump `CACHE` in `sw.js` on every deploy.** If you change Challenge scoring or levels, bump `LB_VERSION` in `14-leaderboard.js` so old runs drop off your personal list.

2. Rule 18 and more traffic, in parts:
   - 2a ✅ Rule 18 vessel types (sail, fishing, NUC, RAM, CBD) with day shapes; two of Mission 1's ships are special.

   - 2c ✅ Mission 2 (Busy crossing): 12 ships in 9 groups, three two-ship moments, mixed types.
   - 2d ✅ Mission 6 (Rogue ships): give-way ships that hold on; stand on, five short, then act (Rules 17 & 34(d)).
3. Mission 3, in parts:
   - 3a ✅ Buoyed harbour channel (Region A), keep to starboard (Rule 9(a)), blind-bend signal (9(f) & 34(e)), grounding, outbound ships meeting you.

   - 4a ✅ Mission 4 (Night passage): radar echoes on the chart, lights in a bridge view, lights explained after each encounter.
